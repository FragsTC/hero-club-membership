# Window Hero email templates: handoff

Read this first. It tells a new session everything needed to edit these email templates or build more.

## What this is

HTML email templates for Window Hero (exterior cleaning franchise; the user runs the Raleigh-Durham location). They are pasted into **ServiceMinder**, the company's field-service CRM, which sends them and fills in `{shortcodes}`.

Twenty-three customer templates exist. Three are rebuilds of the user's originals, seven are general-purpose additions, and thirteen are for the Hero Club membership (added 2026-11-20; see `HERO-CLUB-EMAILS.md`). All are generated by one script from shared building blocks so they stay consistent.

This kit now lives in the `hero-club-membership` repository under `email-templates/`. The Hero Club welcome emails read plan contents from `../public/index.html`, so the build must be run from inside that repository.

## Status: what is and is not verified

- **Verified:** every template renders correctly in a desktop browser and at 375px phone width, with no sideways scrolling and no broken images.
- **Not verified:** nothing has been pasted into ServiceMinder or test-sent. Rendering in Outlook desktop, Gmail and Apple Mail is unconfirmed. The markup follows known-safe email patterns, but treat it as untested until a real send.
- **Not verified:** whether ServiceMinder's editor (it appears to be Froala) keeps the `<style>` block in the head, the hidden preheader `div`, and the `mso-padding-alt` button style. If it strips them, emails still work but lose phone-specific layout, inbox preview text, or Outlook button padding.

## How to work on it

Build (no dependencies, Python 3 standard library only):

```bash
python3 build_emails.py
```

Preview (the preview page uses `fetch`, so it needs a server; opening `index.html` by double-click will not work):

```bash
python3 -m http.server 4173
```

Then open `http://localhost:4173/`.

### Adding a template

1. Write a function in `build_emails.py` that builds a body string from the blocks below and returns `page(title, preheader, body, footer(tagline))`.
2. Add `("file-name.html", function_name)` to the list at the bottom of the script.
3. Add `["file-name", "Display name"]` to `TEMPLATES` in `index.html`. If it has `fillin()` blanks, add sample values to `HANDFILL` there.
4. Add made-up values for any new shortcodes to `SAMPLE` in `index.html` (link shortcodes go in `LINKS`).
5. Build, then check in the preview at both widths and in both data modes.

### Building blocks in `build_emails.py`

| Function | Use |
|---|---|
| `page(title, preheader, body, foot)` | Whole document: head, header image, body cell, footer. |
| `footer(tagline, extra="")` | Navy footer: logo, "Need Assistance?", tagline, phone button, legal lines, unsubscribe. |
| `greeting()` | "Hey {contact.first_name}," |
| `intro(text)` / `closing(text)` | Opening paragraph (18px navy) and centred sign-off. |
| `hero(title, text, extra="")` | Navy headline card with the email's one `h1`. Put the main button in `extra`. |
| `summary(title, rows, note=None)` | Cream "at a glance" card of label/value rows, optional gold-edged note. |
| `ticks(title, items)` | Light card with a single-column tick list. |
| `card(inner, bg, border, align, color)` | Generic rounded box. |
| `callout(inner, top=0)` | White note with a gold left edge. |
| `button(href, label, size, bg, fg, newtab)` | Outlook-safe button. Gold on navy is the primary; navy with white text is secondary. |
| `check_rows(items, color, cols)` | Tick list, two columns on desktop that stack on phones. |
| `proposal_cta(title, text, extra="")` | Navy card with the approve button, "No login required", and PDF link. |
| `white_link(href, label)` | Small underlined white link for use inside navy cards. |
| `heading()`, `p()`, `spacer()`, `spacer_block()` | Text and vertical spacing. |
| `fillin(label)` | A blank the office types over before sending, printed as `[LABEL]` in bold. Used where ServiceMinder has no shortcode. |
| `load_tiers()` | Reads the plans from the signup page so the welcome emails match it. |

`PHONE` and `EMAIL` are the tappable contact lines used in proposal emails.

**Important:** shortcodes use `{braces}`, so the script never uses f-strings or `str.format`. Keep it that way: build strings with `+`.

## Design rules

- **Colors:** navy `#003b64` (header, footer, headings, key text), gold `#fcaf17` (buttons, accents), body grey `#4f5b66`, page background `#f4f6f9`, cream card `#fff9e8` with border `#f1d38a`, light card `#f7f9fc` with border `#d9e2ec`. Use only these. The originals had two navies and four text colors; that was cleaned up on purpose.
- **Font:** Arial, Helvetica, sans-serif. Body 16px, intro 18px, hero headline 28px (24px on phones).
- **Width:** 600px container, fluid below that.
- **Images:** header `141668-WH_Emailhead_2.jpg` (515px wide) and footer `141668-WH_Logo_WH_Logo_White.png` (255px), both at `https://d1m4vp65okes21.cloudfront.net/t/o/2034/e/`. Both confirmed loading over https.
- **Tone:** warm, plain, second person. Greeting is always "Hey {first name},". Headlines are short and title-cased. No hype.
- **One main button per email**, gold, inside the navy hero card.

## Email-client rules (why the markup looks the way it does)

- Layout is **tables with `role="presentation"`**, not `div`s. Desktop Outlook ignores padding and margin on `div`s.
- **Padding goes on `td`**, and vertical gaps use spacer rows, not margins on tables.
- **Buttons** are a `td` with a background color and `mso-padding-alt`, wrapping a padded link. Outlook ignores padding on links.
- **Images** carry a `width` attribute as well as CSS, or Outlook shows them at native size.
- **No `rgba()`, no CSS shorthand tricks, no flexbox or grid.** Outlook does not support them.
- **All styles inline.** The only `<style>` block holds the phone media query; the email must still look right without it.
- **Phone classes:** `.px` (side padding), `.card`, `.stack` (columns become rows), `.photo` / `.details` (manager card), `.h1`, `.btn`.
- Keep each file **well under 102KB** or Gmail clips it. Current files are 7 to 15KB.
- Every email needs a `<title>`, a preheader, alt text on images, and the unsubscribe link plus physical address in the footer.

## Decisions the user has made

- **919-746-4485 stays hardcoded** as the Call/Text number in all proposal emails. Do not replace it with a shortcode.
- **"Completed By"** in the service-complete email uses `{service_agent.names}` (everyone assigned), changed from `{service_agent.additionalnames}`.

## Open items

1. **Commercial proposal manager card** still hardcodes the user's photo and the title "Director of Sales & Operations" beside `{proposal.owner_name}`. If someone else owns a proposal, their name shows with the user's photo and title. The user has not decided what to do. `{proposal.owner_email}` and `{proposal.owner_phone}` exist if wanted.
2. **Manager photo is hosted on ImgBB** (`i.ibb.co`), a free host that can remove images and that some corporate filters block. It should move to the CloudFront storage used for the logos.
3. **Unsubscribe shortcode:** the user's originals use `{unsubscribe.url}`; ServiceMinder's docs list `{unsubscribe_url}`. The original spelling was kept everywhere. Confirm by clicking it in a test send.
4. **Confirm button** (`{appointment.confirm_url}`) only applies when online scheduling is enabled in ServiceMinder. If it is off, swap the button for Add to Calendar.
5. **Draft wording the user has not approved:** the "How to Prepare" checklist (`PREP`), the "Why We Reschedule" reasons, "You don't need to be home for most exterior services", and the Hero Club "What Happens Next" steps.
6. **Hero Club welcome** is now three files, one per plan, because ServiceMinder has no membership shortcodes. Price is still not shown.
7. **Reschedule notice** is for sending by hand **after** moving the appointment, because it shows the contact's next appointment. ServiceMinder has no reschedule template; moving an appointment re-sends the confirmation.
8. **Appointment reminder:** no dedicated reminder template type was found in the docs, so it uses contact-level "next appointment" shortcodes, which work in any template.
9. **Empty first name** renders "Hey ,". No conditional syntax was confirmed, so this is not handled.
10. **Footer year** is typed in as 2026 (`YEAR` in the script). `{current_date}` exists but gives a full date, not a year.
11. **Subject lines** exist for the Hero Club set only (`HERO-CLUB-EMAILS.md`). The other ten have none.
12. **Service-complete aftercare notes** are generic: every customer gets roof-wash and sprinkler notes whatever service they had.
13. **Footer address** is the corporate one (107 Parr Drive, Huntersville, NC), copied from the originals.

## Testing checklist for the user

1. Paste one template into ServiceMinder's source view, save, reopen, and check whether the `<style>` block and the hidden preheader line survived.
2. Send a test of each from a real appointment, proposal or invoice so shortcodes fill in.
3. Open each test in Outlook desktop, Gmail, and on a phone.
4. Check these fields in particular: Completed By, the proposal expiry date, both proposal links, the invoice `{url}` button, the tap-to-call button, and the unsubscribe link.

## What the audit of the originals found

Useful if the user brings more old templates. The three originals all had:

- buttons built as padded links, and cards built as padded `div`s, both of which break in desktop Outlook;
- images over `http://` with no `width` attribute;
- no viewport tag or phone rules;
- an empty `<title>`, no charset, no `lang`, no preheader;
- a footer reading © 2025;
- editor leftovers (stray underlines, off-brand colors, odd font sizes) from ServiceMinder's visual editor.
